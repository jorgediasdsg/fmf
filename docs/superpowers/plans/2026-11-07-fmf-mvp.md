# FMF — MVP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Jogo 2D jogável do início ao fim do MVP — título → Fase 1 → chefe → vitória — exportado para web, Android (APK no Moto G6 Plus) e Linux.

**Architecture:** Projeto Godot 4.7 em GDScript. Um autoload `GameState` guarda stats/progresso/save; cenas separadas para player, inimigos, HUD, título e fase. Assets de pixel art e áudio gerados por scripts Python reprodutíveis em `tools/`. Lógica pura (XP, vida, save) testada headless; cenas verificadas por smoke test de carga.

**Tech Stack:** Godot 4.7.2 (GDScript), Python 3 + Pillow (geração de sprites), Python `wave` (áudio), adb (deploy Android).

**Spec:** `docs/superpowers/specs/2026-11-07-fmf-design.md`

## Global Constraints

- Viewport base 480×270, stretch `canvas_items`, filtro nearest (pixel art nítida).
- Todas as ações de input mapeadas tripla­mente: teclado, joypad e toque (overlay touch só aparece em tela de toque).
- Vida: 15 pontos = 5 corações × 3 terços. Morte → recarrega a fase inteira.
- Textos do jogo em pt-BR com acentuação correta.
- Sem dinheiro real; sem conteúdo assustador/sangue (derrota de inimigo = puff).
- Binários do Godot e builds não entram no git (`.gitignore`); scripts de geração de assets entram, PNGs/WAVs gerados entram (são pequenos e o itch.io precisa deles).
- Godot roda headless via `~/.local/bin/godot`.

## Review Focus

- Jogador cai fora do mapa (buraco sem chão): deve morrer e reiniciar a fase, não cair para sempre. → teste na Task 6.
- Dano repetido no mesmo contato: invencibilidade de 1 s pós-dano para não perder 5 corações num encostão. → teste na Task 4.
- Save corrompido/ausente em `user://`: jogo abre como novo jogo, sem crash. → teste na Task 1.
- Atacar segurando o botão não pode dar dano contínuo: um golpe por pressionada, com cooldown. → teste na Task 4.
- Rotação/resize da janela web e tela do celular (aspect ≠ 16:9): HUD ancorada, sem cortar corações nem botões de toque. → verificação visual na Task 8.

### Task 1: GameState (autoload) + save + testes headless

**Files:**
- Create: `src/autoload/game_state.gd`, `tests/test_game_state.gd`, `tests/run_tests.gd`

**Interfaces:**
- Produces (usado por todas as tasks seguintes): autoload `GameState` com
  `max_hp := 15`, `hp: int`, `coins: int`, `xp: int`, `level: int`,
  `attack_damage() -> int` (= 3 + level), `xp_to_next() -> int` (= 20 * level),
  `add_xp(n)` (sobe nível em cascata, emite `leveled_up`), `add_coins(n)`,
  `take_damage(n) -> bool` (true se morreu; clampa em 0, emite `hp_changed`),
  `heal_full()`, `phases_done: Array[int]`, `complete_phase(i)` (salva),
  `save() / load_save()` (JSON em `user://fmf_save.json`), `reset_run()`
  (vida cheia no início de fase), sinais `hp_changed`, `coins_changed`,
  `xp_changed`, `leveled_up`.

- [ ] **Step 1: Escrever testes** em `tests/test_game_state.gd` — asserts: dano acumulado mata exatamente em 15; `take_damage` nunca negativa; `add_xp(20)` no nível 1 sobe para 2 e carrega excedente; `add_xp` em cascata (muito XP sobe 2+ níveis); save→load round-trip preserva coins/xp/level/phases_done; `load_save()` com arquivo ausente e com JSON inválido retorna estado de jogo novo sem erro. Runner `tests/run_tests.gd` (SceneTree script): executa todos, imprime `ALL TESTS PASSED` ou falhas e `quit(1)`.
